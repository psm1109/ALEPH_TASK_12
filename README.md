#포트폴리오 사이트

정적 사이트입니다. 별도의 설치나 회원 가입이 필요하지 않습니다. 이름, 경험, 실제 기록, 논문과 문서가 제공되지 않아 해당 부분은 빈칸으로 남겼습니다. 이미지 속 예시 이름은 사용하지 않았습니다.

## 확인하기

`index.html`을 브라우저로 열면 됩니다. 또는 이 폴더에서 아래 명령으로 열고 `http://localhost:8000`에 접속하세요.

```sh
python -m http.server 8000 --bind 127.0.0.1
```

첫 화면의 버튼과 상단 메뉴는 해당 구역으로 이동합니다. 모바일에서는 대표작과 문서 카드가 세로로 배치됩니다. 자료가 없는 항목은 링크 대신 준비 중으로 표시합니다.

## 내 내용 입력하기

- `content.js`: 이름, 직접 작성한 한 줄 소개, 이야기 3개 장면, 논문, 문서, 연락 수단을 입력합니다.
- 장면의 `date`에는 실제 날짜를 `YYYY-MM-DD`로 입력합니다. 소설의 각색된 부분은 사실로 되돌린 뒤 넣으세요.
- `paper.url`과 문서 `url`에는 공개 주소 또는 `documents/resume.pdf` 같은 상대 경로를 넣습니다. 상대 경로에 해당하는 실제 파일도 함께 넣어야 합니다.
- `contact`에는 공개하기로 정한 수단 하나만 넣습니다. 이메일이면 `url`을 `mailto:내주소`로 지정합니다.
- 다른 사람의 실명과 비밀값은 입력하지 마세요. 실제 자료가 연결되기 전에는 지원용 완성본이 아닙니다.

## 기록을 갱신하는 장치

사이트는 최대 1280px 컨테이너 안에서 좌우 40px 여백을 제외한 1200px를 본문에 사용합니다. ‘내 이야기’도 기록·대표작과 같은 본문 폭입니다. 현재 ‘13주간의 기록’은 달력 왼쪽, 출석·리추얼·제출 현황 카드 오른쪽 세로 배치이며 카드 안의 수치는 2열 표로 압축합니다. 기준일 안내와 상세 버튼은 카드 하단에 배치합니다. 900px 이하에서는 달력 다음에 카드가 이어지고, 640px 이하에서는 수치를 한 열로 표시합니다. 세 카드의 자세히 보기 버튼은 모두 검은 배경·흰 글씨입니다. 날짜 번호 없는 정사각형 달력은 `content.js`의 `records.period`(2026-08-11~2026-11-12) 안에서 월 이동합니다. 처음에는 스냅샷 기준일의 월을 표시합니다.

실제 날짜별 원문은 `data/records-history.js`의 `window.PORTFOLIO_HISTORY`로 관리합니다. `asOf`는 기준일(현재 2026-10-12), `className`은 반 이름, `attendance`는 날짜별 출석 배열, `ritualDays`는 리추얼 원문 배열입니다. 날짜는 YYYY-MM-DD, 날짜마다 한 항목을 사용하며 주말·공휴일 등을 임의로 출석 기록에 추가하지 않습니다.

```js
// 출석: status는 present / excused / absent / pending
{ date: "2026-10-12", status: "pending", symbol: "", entry: "08:21", exit: "", outing: "", note: "" }
// 리추얼: open/close는 원문 문자열 배열 또는 null
{ date: "2026-10-12", open: ["호흡: 5분"], close: null }
```

위 코드는 형식 예시입니다. 실제 원문은 사용자 제공 리추얼 JSON 58일을 모두 보존했습니다. 출석은 채팅으로 제공한 40일의 시각·상태·비고를 입력했습니다. `records-ui.js`가 기준일 안의 출석과 리추얼 원문을 집계합니다. 출석률은 `(present + excused) / 재적일 × 100`이며 확정 전도 재적일에 들어갑니다. 현재 일반 출석 38일·공가 1일·확정 전 1일로 출석 인정 39일, 출석률 97.5%입니다. 리추얼은 기록 58일·아침 58회·마무리 57회·총 115회입니다. ‘아침+마무리’, ‘아침만’ 요약 행은 표시하지 않습니다.

달력은 리추얼 없음=흰색, 아침만=회색, 둘 다=검은색입니다. 마무리만 있는 예외도 1회이므로 회색으로 표시하고 설명에 구분합니다. 파일에 없는 날짜와 기준일 이후 날짜는 흰색이지만 설명에는 미확인이라고 표시합니다. 칸에 초점을 이동하거나 마우스를 올리면 날짜·출석·리추얼 상태를 확인합니다. 기준일 안의 칸을 클릭하면 해당 날짜의 리추얼 상세 모달을 엽니다.

출석 상세는 날짜·기호·상태·입실·퇴실·외출·비고를 표로 표시합니다. 최근 1주는 기준일 포함 7일, 최근 1달은 기준일 포함 30일이며 개강일부터·직접 날짜 선택도 지원합니다. 기간 필터는 표만 바꾸고 누적 요약은 전체 기준을 유지합니다. 리추얼 상세는 날짜 선택·이전/다음 날짜·아침/마무리 전환을 제공하고 동료 피드백·감사 기록은 접어서 펼칩니다. 가져온 문자열은 HTML로 실행하지 않고 텍스트로 표시합니다. 원문에 이미 가려진 동료 이름은 그대로 유지합니다.

‘내 제출 현황’의 버튼은 11건 목록 모달을 엽니다. 목록의 ‘제출 내용 보기’는 기존 상세 모달을 열고 닫으면 목록으로 돌아갑니다. 모든 모달은 닫기·Esc·배경 클릭과 초점 복귀를 지원합니다. 제출 목록과 상태는 `content.js`의 `records.submissions`, 제목·본문은 `submissionContents.Txx.title/body`를 편집합니다. `body`는 기존 HTML 문자열이며 텍스트 특수문자는 HTML 이스케이프합니다. 첨부파일은 이름 목록만 제공됩니다.

숫자를 갱신할 때 JavaScript가 꺼진 경우의 `index.html` 요약, `content.js`의 예비 누적 숫자와 기록 연결 문구도 맞춰주세요. 실제 화면의 숫자는 날짜별 원문에서 계산됩니다. 파일 자동 가져오기 및 능력별 문단 후보 재생성은 아직 구현하지 않았습니다. 향후 가져오기 장치는 위 `PORTFOLIO_HISTORY` 구조를 생성하면 화면이 그 데이터를 집계합니다.

아래 집계 도구는 날짜별 계획·완료·다시 시작 기록을 별도로 정리하는 도구입니다. 출석 일수와 리추얼 일수로 기록 주 수나 다시 시작한 횟수를 추정하지 않습니다.

Python 3.10 이상, 외부 라이브러리나 API 키 없이 실행됩니다. `data/records.json`에 실제 기록을 추가하고 실행하세요.

```sh
python scripts/update_records.py
```

입력 형식 예시입니다. 아래 숫자는 설명용이며 사이트에 반영되어 있지 않습니다.

```json
{"records":[{"date":"2026-01-05","planned":4,"completed":3,"restarts":1,"source":"1주차 기록, 2쪽"}]}
```

날짜당 한 기록을 허용합니다. 주간 기록이면 매주 동일한 기준 날짜를 사용하세요. `planned`는 계획한 과제 수, `completed`는 완료한 과제 수, `restarts`는 중단 후 다시 시작한 행동 횟수입니다. 출처에는 공개할 수 있는 문서명·날짜·쪽수를 남기세요.

기록 기간은 기록이 존재하는 ISO 주의 개수입니다. 빈 주는 포함하지 않습니다. 과제 지속률은 `완료 건수 / 계획 건수 × 100`입니다. 계획이 0건이면 계산하지 않습니다. 다시 시작한 횟수는 행동 지표이며 심리검사 점수가 아닙니다. 13주가 채워지기 전에는 실제 입력한 주 수만 표시합니다.

결과는 `records-result.json`, JavaScript 형식의 `records-result.js`, 검토용 `paragraph-candidates.md`입니다. 현재 페이지는 이 결과 파일을 자동으로 읽지 않습니다. 문단 후보는 사실 기반 초안이며 본문에 자동 적용하지 않습니다. 검토한 문장만 `content.js`에 반영하세요. 입력이 잘못되면 기존 결과를 보존한 채 오류로 종료합니다.

같은 입력을 새 폴더 두 곳에서 실행하여 세 결과 파일의 내용을 비교할 수 있습니다.

```sh
python scripts/update_records.py --output .checks/first
python scripts/update_records.py --output .checks/second
```

## 공개하기

‘10번 · 논문’에는 `assets/papers/t10-paper.md` 원본 다운로드와 Markdown 모달 보기를 제공합니다. 원문을 바꾼 뒤 `python scripts/build_paper.py`를 실행하면 `data/paper-markdown.js`가 갱신됩니다. Python 표준 라이브러리만 사용하며 다운로드 원본 파일은 변경하지 않습니다. 이 JS 문자열을 사용하는 이유는 `file://`로 사이트를 직접 열어도 추가 요청 없이 논문을 표시하기 위해서입니다. 제목·요약·다운로드 경로·파일 이름은 `content.js`의 `paper`에서 관리합니다.

`paper-view.js`는 로컬에 포함한 Marked 17.0.5(`assets/vendor/marked.umd.js`, MIT 라이선스 전문: `assets/vendor/marked-LICENSE.md`)로 표·목록·코드·링크 서식을 적용합니다. HTML 원문은 텍스트로 처리하고 허용한 요소와 안전한 링크 프로토콜만 표시합니다. 숫자 범위의 단일 `~`는 그대로 표시하며 `~~취소선~~`처럼 물결표 두 개를 쓴 경우에만 취소선을 적용합니다. 표와 코드 블록은 가로 스크롤할 수 있으며 보기 모달은 기존 닫기·Esc·배경 클릭·초점 복귀를 사용합니다. JavaScript가 꺼진 경우에도 원본 다운로드는 가능합니다. 이번 제공 파일은 논문 Markdown이며 논문에서 언급하는 분석 ZIP·CSV·코드는 별도 포함하지 않습니다.

이 폴더의 `index.html`, `styles.css`, `app.js`, `records-ui.js`, `paper-view.js`, `content.js`, `data/records-history.js`, `data/paper-markdown.js`, `assets`와 직접 등록한 문서 파일을 정적 웹 호스팅에 올리면 됩니다. 사이트는 방문자 통계, 댓글, 로그인, 외부 API 호출을 사용하지 않습니다. 이번 작업에서는 전체 소스 작성과 로컬 확인까지만 진행합니다.
