# 포트폴리오 사이트

개인 이야기와 리추얼·출석·과제 제출 기록을 보여 주는 정적 사이트입니다. 사이트 보기는 별도 설치나 회원 가입 없이 가능하며, JSON 기록 갱신에는 Node.js 20 이상이 필요합니다. 아직 작성하지 않은 지원 문서는 준비 상태로 유지합니다.

## 확인하기

`index.html`을 브라우저로 열면 됩니다. VS Code의 Live Server 등 기존 정적 서버로 열어도 됩니다.

첫 화면의 버튼과 상단 메뉴는 해당 구역으로 이동합니다. 모바일에서는 대표작과 문서 카드가 세로로 배치됩니다. 자료가 없는 항목은 링크 대신 준비 중으로 표시합니다.

## 내 내용 입력하기

- `content.js`: 이름, 직접 작성한 한 줄 소개, 이야기 6개 장면, 논문, 문서, 연락 수단을 입력합니다. ‘내 이야기’의 제목·날짜·본문·역량 요약은 `story` 배열에서만 관리하며 `index.html`에 복사하지 않습니다. `app.js`가 표시 영역을 채우며 JavaScript 비활성화 시 안내 문구가 표시됩니다.
- 장면의 `date`에는 단일 날짜 또는 월을 `YYYY-MM-DD` 또는 `YYYY-MM`으로 입력합니다. 기간은 `date`를 비우고 `dateLabel`에 `2018.11 ~ 2019.09`처럼 입력합니다. 소설의 각색된 부분은 사실로 되돌린 뒤 넣으세요.
- `paper.url`과 문서 `url`에는 공개 주소 또는 `documents/resume.pdf` 같은 상대 경로를 넣습니다. 상대 경로에 해당하는 실제 파일도 함께 넣어야 합니다.
- `contact`에는 공개하기로 정한 수단 하나만 넣습니다. 이메일이면 `url`을 `mailto:내주소`로 지정합니다.
- 다른 사람의 실명과 비밀값은 입력하지 마세요. 실제 자료가 연결되기 전에는 지원용 완성본이 아닙니다.

## 기록을 갱신하는 장치

사이트는 최대 1280px 컨테이너 안에서 좌우 40px 여백을 제외한 1200px를 본문에 사용합니다. ‘내 이야기’도 기록·대표작과 같은 본문 폭입니다. 현재 ‘13주간의 기록’은 달력 왼쪽, 출석·리추얼·제출 현황 카드 오른쪽 세로 배치이며 카드 안의 수치는 2열 표로 압축합니다. 기준일 안내와 상세 버튼은 카드 하단에 배치합니다. 900px 이하에서는 달력 다음에 카드가 이어지고, 640px 이하에서는 수치를 한 열로 표시합니다. 세 카드의 자세히 보기 버튼은 모두 검은 배경·흰 글씨입니다. 날짜 번호 없는 정사각형 달력은 `content.js`의 `records.period`(2026-08-11~2026-11-12) 안에서 월 이동합니다. 처음에는 스냅샷 기준일의 월을 표시합니다.

아래는 초기 스냅샷 구조 설명입니다. 갱신 후 실제 표시는 `data/records-import.js`가 우선하며, 초기 날짜별 원문은 `data/records-history.js`의 `window.PORTFOLIO_HISTORY`에 보관합니다. `asOf`는 기준일(초기 보관본 2026-10-12), `className`은 반 이름, `attendance`는 날짜별 출석 배열, `ritualDays`는 리추얼 원문 배열입니다. 날짜는 YYYY-MM-DD, 날짜마다 한 항목을 사용하며 주말·공휴일 등을 임의로 출석 기록에 추가하지 않습니다.

```js
// 출석: status는 present / excused / absent / pending
{ date: "2026-10-12", status: "pending", symbol: "", entry: "08:21", exit: "", outing: "", note: "" }
// 리추얼: open/close는 원문 문자열 배열 또는 null
{ date: "2026-10-12", open: ["호흡: 5분"], close: null }
```

위 코드는 형식 예시입니다. 실제 원문은 사용자 제공 리추얼 JSON 58일을 모두 보존했습니다. 출석은 채팅으로 제공한 40일의 시각·상태·비고를 입력했습니다. `records-ui.js`가 기준일 안의 출석과 리추얼 원문을 집계합니다. 출석률은 `(present + excused) / 재적일 × 100`이며 확정 전도 재적일에 들어갑니다. 초기 보관본은 일반 출석 38일·공가 1일·확정 전 1일, 리추얼 58일·115회였습니다. 현재 승인한 2026-10-15 기준 입력은 출석 43일(일반 출석 41일·공가 1일·확정 전 1일), 출석 인정 42일·97.7%, 리추얼 60일·아침 60회·마무리 60회·총 120회입니다. ‘아침+마무리’, ‘아침만’ 요약 행은 표시하지 않습니다.

달력은 리추얼 없음=흰색, 아침만=회색, 둘 다=검은색입니다. 마무리만 있는 예외도 1회이므로 회색으로 표시하고 설명에 구분합니다. 파일에 없는 날짜와 기준일 이후 날짜는 흰색이지만 설명에는 미확인이라고 표시합니다. 칸에 초점을 이동하거나 마우스를 올리면 날짜·출석·리추얼 상태를 확인합니다. 기준일 안의 칸을 클릭하면 해당 날짜의 리추얼 상세 모달을 엽니다.

출석 상세는 날짜·기호·상태·입실·퇴실·외출·비고를 표로 표시합니다. 최근 1주는 기준일 포함 7일, 최근 1달은 기준일 포함 30일이며 개강일부터·직접 날짜 선택도 지원합니다. 기간 필터는 표만 바꾸고 누적 요약은 전체 기준을 유지합니다. 리추얼 상세는 날짜 선택·이전/다음 날짜·아침/마무리 전환을 제공하고 동료 피드백·감사 기록은 접어서 펼칩니다. 가져온 문자열은 HTML로 실행하지 않고 텍스트로 표시합니다. 원문에 이미 가려진 동료 이름은 그대로 유지합니다.

‘내 제출 현황’의 버튼은 11건 목록 모달을 엽니다. 목록의 ‘제출 내용 보기’는 기존 상세 모달을 열고 닫으면 목록으로 돌아갑니다. 모든 모달은 닫기·Esc·배경 클릭과 초점 복귀를 지원합니다. 최신 제출 목록·상태·새 본문은 `record-input/submissions.json`에서 관리합니다. 초기 제출 본문은 `content.js`의 `submissionContents.Txx.title/body`에 보관하며 새 body가 비어 있으면 같은 코드의 초기 본문을 유지합니다. `body`는 기존 HTML 문자열이며 텍스트 특수문자는 HTML 이스케이프합니다. 첨부파일은 이름 목록만 제공됩니다.

### JSON 파일로 한 번에 갱신하기

`record-input/`의 `manifest.json`, `rituals.json`, `attendance.json`, `submissions.json` 네 파일을 전체 누적 기록으로 준비한 뒤 다음 명령 하나를 실행하세요. 현재 이 폴더에는 실제 수신 기록이 들어 있습니다.

```powershell
node scripts/import_records.js
```

**출석·리추얼·과제 제출 내역**을 확인한 뒤 `y`를 입력하고 장면 선택에서 `1`(기존 유지) 또는 `2`(새 후보)를 고르면 `generated/` 결과 생성과 `data/records-import.js` 교체까지 한 번에 처리합니다. 승인 파일 작성·문단 ID 복사·사이트 파일 수동 복사는 필요하지 않습니다. 브라우저를 새로고침하면 적용되며 공개 사이트는 다시 배포해야 반영됩니다. 커밋·push·배포는 자동 수행하지 않습니다.

- 확인 질문 없이 현재 기록 반영 및 기존 장면 유지: `node scripts/import_records.js --yes`
- 사이트를 바꾸지 않고 결과만 확인: `node scripts/import_records.js --preview`
- 다른 입력 폴더: `node scripts/import_records.js --input 폴더경로`

`--yes` 실행은 그 실행의 세 가지 기록과 관련 숫자에 대한 승인입니다. `privacyReviewed`도 확인해야 하며 오류·취소 시 기존 사이트를 유지합니다. 기본 실행에는 별도의 승인 파일이 필요하지 않습니다.

| manifest 항목 | 갱신 기준 |
|---|---|
| `version` | 형식 버전 1 유지. 갱신 횟수가 아닙니다. |
| `period.start` | 기존 시작일 유지 |
| `period.end` | 전체 기간 종료일. 기간 연장 때만 변경 |
| `asOf` | 세 파일을 종합한 마지막 확인 기록 날짜. 편집일과 다릅니다. |
| `privacyReviewed` | 타인 실명·연락처·비밀값을 제거한 뒤 true |

예를 들어 리추얼은 10월 14일, 출석은 10월 15일, 과제는 10월 7일까지 있어도 asOf는 2026-10-15입니다. 각 파일에는 새 기록뿐 아니라 **전체 누적 내역**을 넣어야 합니다. 기록 날짜는 시작일~기준일, 기준일은 종료일 안에 있어야 합니다.

자동 갱신 대상은 **출석·리추얼·과제 제출 기록과 집계·기준일·기간**, 그리고 **실행 중 선택한 리추얼 장면 하나**입니다. 내 이야기·소개·논문·문서·연락처는 유지합니다.

터미널에서 기존 문구와 새 후보의 제목·설명·본문·출처를 비교하고 `1`은 기존 유지, `2`는 후보 반영, `0` 또는 Enter는 전체 취소를 선택합니다. 후보는 본인의 ‘강점이 드러난 일화’에서 도움·설명·공유 기록 우선, 그 안에서는 최신순으로 하나만 발췌하며 본문을 각색하지 않습니다. 후보가 없으면 기존 유지/취소만 제공합니다. 현재 사이트의 제목·설명·장면 제목·문장별 줄바꿈·날짜와 아침/마무리 출처 형식을 유지합니다.

`--yes`는 기존 장면을 유지합니다. 새 후보까지 승인해 자동 반영하려면 `node scripts/import_records.js --yes --excerpt candidate`를 사용하세요. 초기 장면은 content.js의 JSON 형식 ritualExcerpt, 이후 장면은 data/records-import.js의 마지막 승인 내용이 우선합니다. 비교와 근거는 generated/ritual-candidate.md, 선택 영수증은 generated/applied-approval.json에 저장됩니다. 같은 입력과 같은 승인 문구는 같은 공개 결과를 만듭니다.

과제 `body`가 비어 있으면 `content.js`에 보관된 같은 코드의 기존 본문을 유지합니다. 새 본문이 있으면 일반 텍스트로 안전하게 표시합니다. 이야기·리추얼·고정한 장면의 줄바꿈은 유지합니다.

[전체 입력 형식·실행 세 단계·오류 해결](docs/RECORD_IMPORT.md)을 참고하세요. 검사: `node --test scripts/test_import_records.js`. 사이트를 제외한 장치 ZIP(코드·입력·README·마지막 결과와 승인·비교) 생성: `node scripts/package_records.js`. 제출 파일은 `deliverables/record-updater-device.zip`이며, 별도 사이트 연결은 ZIP의 README에 있는 `--site-root` 명령을 사용합니다.

## 지원 문서

`assets/documents/self-introduction.docx`와 `assets/documents/project-experience.docx`는 나중에 작성할 자기소개서·경력기술서입니다. 사용자 요청으로 기존 본문과 생성용 원문 데이터를 비웠으며 현재 파일에는 이름과 문서 제목만 있습니다. 다운로드 기능과 파일 경로는 유지합니다. 이력서는 사용자가 별도로 작성 중이므로 이번 산출물에 포함하지 않았습니다.

두 Word 파일은 사이트 문서 영역에서 내려받을 수 있고 JavaScript를 끈 경우에도 링크가 작동합니다. 내용과 출처는 `assets/documents/application-content.json`, 생성기는 `scripts/build_application_documents.py`에서 관리합니다. Python과 `python-docx`가 필요합니다. Codex에서는 `load_workspace_dependencies`가 반환한 Python 경로로 아래 명령을 실행합니다.

```sh
python scripts/build_application_documents.py
```

자기소개서는 JSON의 `introduction.field`(선택 지원 분야), `title`, `paragraphs`에 내용을 입력합니다. 경력기술서는 `experience.scope`, `role`, `projects`에 내용을 입력합니다. 과제 항목은 `code`, `title`, `submitted`, `ability`, `situation`, `action`, `result`를 사용합니다. 과제를 채울 때 `asOf`도 입력합니다. 내용이 비어 있으면 생성기는 본문·표·기준일을 넣지 않습니다. 원문 변경 후 문서를 다시 생성하고 Word에서 내용과 페이지 배치를 확인하세요. 배포 시 `assets/documents/`를 함께 포함합니다. 원본 카드·제출 기록이 바뀌더라도 문서는 자동으로 변경되지 않습니다.

## 논문과 배포

‘AI와 함께 쓰는 첫 논문 - 가설에서 결론까지’에는 `assets/papers/t10-paper.md` 원본 다운로드와 Markdown 모달 보기를 제공합니다. 원문을 바꾼 뒤 `python scripts/build_paper.py`를 실행하면 `data/paper-markdown.js`가 갱신됩니다. Python 표준 라이브러리만 사용하며 다운로드 원본 파일은 변경하지 않습니다. 이 JS 문자열을 사용하는 이유는 `file://`로 사이트를 직접 열어도 추가 요청 없이 논문을 표시하기 위해서입니다. 주제목(title)·부제목(summary)·설명(description)·다운로드 경로·파일 이름은 `content.js`의 `paper`에서 관리합니다. 모달 상단 제목은 부제목(summary)을 사용하며 논문 원문 제목은 그대로 표시합니다.

`paper-view.js`는 로컬에 포함한 Marked 17.0.5(`assets/vendor/marked.umd.js`, MIT 라이선스 전문: `assets/vendor/marked-LICENSE.md`)로 표·목록·코드·링크 서식을 적용합니다. HTML 원문은 텍스트로 처리하고 허용한 요소와 안전한 링크 프로토콜만 표시합니다. 숫자 범위의 단일 `~`는 그대로 표시하며 `~~취소선~~`처럼 물결표 두 개를 쓴 경우에만 취소선을 적용합니다. 표와 코드 블록은 가로 스크롤할 수 있으며 보기 모달은 기존 닫기·Esc·배경 클릭·초점 복귀를 사용합니다. JavaScript가 꺼진 경우에도 원본 다운로드는 가능합니다. 이번 제공 파일은 논문 Markdown이며 논문에서 언급하는 분석 ZIP·CSV·코드는 별도 포함하지 않습니다.

이 폴더의 `index.html`, `styles.css`, `app.js`, `records-ui.js`, `paper-view.js`, `content.js`, `data/records-history.js`, `data/records-import.js`, `data/paper-markdown.js`, `assets`와 직접 등록한 문서 파일을 정적 웹 호스팅에 올리면 됩니다. 사이트는 방문자 통계, 댓글, 로그인, 외부 API 호출을 사용하지 않습니다. 이번 작업에서는 전체 소스 작성과 로컬 확인까지만 진행합니다.

## AI와 나의 판단
