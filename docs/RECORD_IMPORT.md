# JSON 네 파일로 사이트 갱신하기

Node.js 20 이상이면 실행할 수 있습니다. 외부 패키지 설치(npm install)·Python·API 키·네트워크는 필요 없습니다. 터미널에서 `node --version`으로 설치 여부를 확인하세요. 현재 `record-input/`에는 사용자가 제공한 실제 누적 기록이 들어 있습니다. 아래 JSON은 형식 설명용입니다.

## 실행 방법 세 단계

1. `record-input/`의 `manifest.json`, `rituals.json`, `attendance.json`, `submissions.json`을 **전체 누적 기록**으로 채웁니다. 타인 실명·연락처·비밀값을 제거하고 `privacyReviewed`를 `true`로 지정합니다.
2. 저장소 루트에서 아래 명령을 실행합니다. 출석·리추얼·과제 제출 집계가 터미널에 표시됩니다. 원문·공개 범위를 확인하고 `y`를 입력합니다. 이어서 기존 문구와 새 후보의 제목·설명·본문·출처를 읽고 `1`(기존 유지) 또는 `2`(후보 반영)를 선택하면 생성과 사이트 파일 교체가 완료됩니다. 첫 질문의 `n`/Enter 또는 장면 선택의 `0`/Enter/입력 종료는 전체 취소이며 기존 사이트와 생성 파일을 유지합니다.

   ```powershell
   node scripts/import_records.js
   ```

3. `index.html`을 열거나 브라우저를 새로고침합니다. 명령이 갱신한 `data/records-import.js`는 파일로 저장되므로 브라우저를 닫아도 유지됩니다. **공개 사이트에는 이 파일을 포함해 재배포해야 반영됩니다.** Git 커밋·push·배포는 스크립트가 수행하지 않습니다.

승인 파일 작성·문단 ID 복사·생성 파일의 수동 복사는 기본 절차에서 필요하지 않습니다. 명령 기본 경로는 실행한 위치가 아니라 스크립트가 들어 있는 저장소를 기준으로 합니다. 다른 입력 폴더를 쓰려면 `--input 경로`를 지정합니다.

## 자동 실행과 미리보기

이미 내용을 확인했고 질문 없이 현재 기록을 반영하고 기존 장면을 유지하려면:

```powershell
node scripts/import_records.js --yes
```

`--yes`를 실행하는 행위가 **그 실행의 출석·리추얼·제출 내역과 관련 숫자에 대한 반영 승인**입니다. 이 옵션은 기존 장면을 유지합니다. 새 후보까지 명시적으로 승인하려면 `node scripts/import_records.js --yes --excerpt candidate`를 사용하세요. 후보가 없으면 해당 명령은 오류로 종료해 전체 반영을 막습니다. 모든 기록을 읽는 데이터 파일이 사이트에 포함되므로 개인정보는 실행 전에 제거해야 합니다.

사이트를 바꾸지 않고 검토 파일만 만들려면:

```powershell
node scripts/import_records.js --preview
```

`generated/records-result.json`에는 세 기록·집계·새 후보와 근거가, `generated/records-review.md`에는 집계와 두 문구 비교가, `generated/ritual-candidate.md`에는 기존 문구·새 후보·원문 근거가 저장됩니다. 미리보기의 JS는 null이며 **사이트 data 폴더의 JS는 건드리지 않습니다.** 예전 자동 발췌 파일인 paragraph-candidates.md는 생성하지 않고 기존 파일도 갱신 트랜잭션에서 제거합니다.

실제 반영 시 `generated/applied-approval.json`에 해당 실행의 snapshotId·excerptChoice·선택한 ritualExcerpt를 기록합니다. 기본 실행에는 승인 파일이나 장면 ID가 필요 없습니다. 선택 사항인 `--approvals 파일경로`를 명시하면 현재 snapshotId의 승인 파일을 사용할 수 있습니다. 템플릿 기본 선택은 current이며 ritualExcerpt에 기존 문구가 들어 있습니다. candidate로 바꾸려면 excerptChoice를 candidate로 바꾸고 ritualExcerpt 항목을 제거해 새 후보를 사용하거나 후보의 네 필드를 정확히 복사합니다. 선택 없는 이전 승인과 이전 장면 ID 승인은 거절합니다.

## 갱신 범위와 장면 선택

자동 갱신 대상은 **출석·리추얼·과제 제출 기록과 집계/기준일/기간**이며, 추가로 실행 중 선택한 **‘리추얼에서 고른 한 장면’ 하나**만 반영합니다. 내 이야기·소개·논문·문서·연락처는 유지합니다. 과제 본문은 새 body를 제공했을 때 바꾸며 빈 body는 아래 보존 규칙을 따릅니다.

현재 장면은 2026-09-11 아침 ‘어려움을 겪는 동료에게 먼저 다가가다’입니다. 처음에는 content.js의 ritualExcerpt에서 읽고, 이후에는 마지막 승인 스냅샷의 ritualExcerpt가 우선합니다. 기존 유지 선택은 마지막으로 승인한 장면을 유지하며 해당 날짜가 새 입력에서 빠져도 사라지지 않습니다. 초기 ritualExcerpt는 네 문자열 필드(title/body/source/description)의 **JSON 객체 문법(큰따옴표, 주석·마지막 쉼표 없음)**을 유지하세요. 스크립트는 JavaScript를 실행하지 않고 이 객체만 읽습니다.

후보는 rituals.json의 `강점이 드러난 일화: 내용`에서 본인 일화 하나만 발췌합니다. 동료를 돕거나 설명·공유한 행동의 표현을 포함한 일화를 우선하고, 같은 우선순위에서는 최신 날짜 → 마무리 → 원문 배열의 앞 항목 순으로 정합니다. 해당 표현이 없으면 최근 본인 일화를 사용합니다. 동료 평가·다짐·감사 항목은 후보로 쓰지 않으며 본문은 원문 그대로입니다. 짧거나 해당 항목이 없는 기록만 있으면 후보 없음으로 표시하고 기존 유지/취소만 제공합니다. 이 규칙은 문장의 진위나 성과를 판정하지 않으므로 주체와 문맥은 사람이 검토합니다.

표시 형식은 기존 사이트와 같습니다: ‘리추얼에서 고른 한 장면’ 제목 → 설명 → 장면 제목 → 문장별 줄바꿈한 원문 → `출처: YYYY-MM-DD 아침/마무리 리추얼`. 능력별 후보·중복 날짜 필드·이야기 이동 링크는 추가하지 않습니다. 검토 파일에는 별도로 원문 항목명과 입력 출처도 남깁니다.

같은 네 입력이면 집계·후보·snapshotId가 같습니다. 공개 결과는 입력과 승인한 문구가 같으면 같습니다. 비교 문서의 ‘기존 문구’는 실행 전 사이트 상태에 따라 달라질 수 있습니다. 두 실행 재현 비교는 동일한 입력과 승인 영수증을 사용합니다.

## 입력 파일 형식

파일명은 고정이며 UTF-8 JSON을 사용합니다. JSON 주석은 허용하지 않습니다. 파일에 없는 날짜를 추정하거나 과거 입력에 합치지 않습니다. 매번 전체 누적 내역을 넣어야 하며 빈 배열은 기록 0건을 뜻합니다.

### manifest.json

```json
{
  "version": 1,
  "asOf": "2026-10-15",
  "period": { "start": "2026-08-11", "end": "2026-11-12" },
  "privacyReviewed": true
}
```

| 항목 | 갱신 기준 |
|---|---|
| `version` | 입력 형식 버전. 매번 올리지 않고 현재는 `1` 유지 |
| `period.start` | 기존 기록 시작일 유지 |
| `period.end` | 전체 과정·기록 기간 종료일. 기간을 연장할 때만 변경 |
| `asOf` | 세 파일을 종합해 기록을 확인한 마지막 날짜. 파일 편집일과 다름 |
| `privacyReviewed` | 타인 개인정보·비밀값을 제거했는지 매번 직접 확인 후 true |

리추얼은 10월 14일, 출석은 10월 15일, 과제는 10월 7일까지 있어도 asOf는 10월 15일입니다. 세 자료의 마지막 날짜가 같을 필요는 없습니다. 모든 기록 날짜는 시작일~기준일 안이어야 하며 기준일은 종료일을 넘을 수 없습니다. 날짜는 서울 기준 YYYY-MM-DD입니다.

### attendance.json

```json
{
  "attendance": [
    { "date": "2026-10-15", "status": "pending", "symbol": "", "entry": "08:21", "exit": "", "outing": "", "note": "", "source": "내 출석표 · 2026-10-15" }
  ]
}
```

필수: `date`, `status`, `source`. 나머지는 선택 문자열이며 시각은 HH:MM 또는 빈 문자열입니다. 날짜별 한 항목만 넣습니다. status는 present(출석), excused(공가), absent(결석), pending(확정 전)입니다. 지각·조퇴는 출석 인정 여부에 맞춰 상태를 정하고 symbol/note로 설명합니다. 휴일·미확인 날짜를 임의로 출석으로 넣지 않습니다.

출석률 = `(present + excused) / 입력 훈련일 × 100`, 소수 첫째 자리. 확정 전도 분모에 포함하며 기록이 없으면 계산하지 않습니다.

### rituals.json

```json
{
  "ritualDays": [
    {
      "date": "2026-10-14",
      "open": ["강점이 드러난 일화: 문제의 원인을 찾아 확인했습니다. 결과를 기록했습니다."],
      "close": null,
      "source": "내 리추얼 원문 · 2026-10-14"
    }
  ]
}
```

날짜별 한 항목이며 open/close는 문자열 배열 또는 null입니다. 기존 파일이 days 배열이면 ritualDays로 옮기고 날짜마다 공개 가능한 source를 추가합니다. 없는 회차는 null 또는 []이며 공백뿐인 회차는 집계하지 않습니다. 원문 항목은 `항목명: 내용` 형태로 유지하면 상세 화면에서 항목명과 내용을 구분해 표시합니다.

### submissions.json

```json
{
  "submissions": [
    { "code": "T01", "date": "2026-09-10", "status": "최종 확인 완료", "title": "과제 제목", "body": "", "source": "내 제출 목록 · T01" }
  ]
}
```

나열한 필드는 필수입니다. 코드는 T와 두 자리 이상의 숫자, 날짜는 실제 제출일, 상태는 제출 완료 또는 최종 확인 완료입니다. 재제출은 같은 코드의 마지막 기록 하나만 넣습니다. 첨부파일 수를 과제 수로 세지 않습니다.

`body`에 일반 텍스트를 넣으면 해당 본문으로 표시하며 HTML은 실행하지 않습니다. **빈 문자열은 새 본문 미제공을 뜻하며 content.js에 보관된 같은 과제 코드의 기존 본문을 유지합니다.** 기존 본문도 없으면 ‘아직 제출 본문을 제공하지 않았습니다.’를 표시합니다. 이전 실행에서 입력한 새 본문도 유지하려면 다음 누적 입력의 body에 계속 포함하세요. 목록에서 과제를 빼면 해당 과제는 표시하지 않습니다.

이전 형식의 observations는 호환을 위해 검증·보존하지만 다른 콘텐츠를 생성하거나 변경하는 데 사용하지 않습니다. 새 입력에는 넣을 필요가 없습니다. 다른 임의 키는 오류입니다.

## 실패 시 처리

네 파일 검증과 반영 확인이 끝난 뒤 파일을 준비하고, 사이트 JS를 마지막에 원자적으로 교체합니다. 오류·취소·동시 실행 충돌은 기존 사이트를 보존하며 파일 교체 중 오류는 이전 파일로 복구합니다. 디스크/권한 문제로 복구까지 실패하면 명시적인 복구 오류를 표시하므로 메시지를 확인하세요.

누락 파일은 경로, JSON 문법 오류는 파일명·행·열을 안내합니다. 오류에 실제 비밀값은 출력하지 않습니다. 강제 종료 뒤 data/.records-update.lock이 남았다면 실행 중인 갱신 작업이 없는지 확인하고 해당 파일만 삭제한 뒤 재실행합니다.

## 짧은 확인 방법과 제출 장치

```powershell
node --test scripts/test_import_records.js
node scripts/package_records.js
```

검사는 새 임시 사이트에서 한 명령 실행·두 번 실행 일치·취소·입력 오류·기존/후보 선택·다음 실행의 장면 유지·선택 단계 취소·원문 근거·후보 결정성·다른 콘텐츠 보존·동시 실행·교체 오류 복구를 확인합니다. 패키지는 현재 승인된 입력·실행 소스·사이트·README·마지막 결과·두 실행 비교를 담은 deliverables/record-updater.zip을 만듭니다. 현재 입력이 마지막 반영과 다르면 패키징을 거절하므로 먼저 갱신/승인하세요. ZIP의 comparison.json에는 두 실행의 SHA-256이 있습니다.

privacyReviewed는 사람이 검토했다는 표시이며 완전한 자동 실명·비밀값 검증이 아닙니다. 일반 연락처·비밀값 형태는 차단하지만 원문·출처·파일명도 직접 읽고 확인해야 합니다. 논문의 공개 참고문헌 저자명 등 기존 사이트 자료는 별도 제출 검토가 필요합니다.

## AI와 나의 판단 세 줄

- AI: 입력 검증·세 기록 집계·근거가 붙은 장면 후보 생성·선택 반영과 복구를 구현했습니다.
- 나: 기존 문구와 후보의 날짜·원문·주체·개인정보를 검토하고 공개할 문구를 선택합니다.
- 함께: 실제 기록을 유지하고 확인하지 않은 성과나 능력을 만들어 넣지 않습니다.
